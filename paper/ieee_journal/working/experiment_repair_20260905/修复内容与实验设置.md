# 主实验代码修复与执行设置

本轮任务：把已查明的 E1 实现错误修复到代码，完成同一组 4 户真实模型短运行及统计图表。保留 24 户、100 户主实验设计，以及原来的消融与跨模型实验；不在小样本验收期间启动全量。

## 已落实的修改

| 原问题 | 修复后的行为 |
|---|---|
| 成员位置缺失 | 初始化全部家庭成员，决策居民与照护成员都能追踪 |
| 重复撤离 | 已到安全区不再唤醒；世界再次检查出发地，拒绝重复移动 |
| 漏写同行者时自动补成单人 | 家庭提议必须明确填写同行者、照护成员、车辆与时间；字段缺失不再变成“独自走” |
| 提议先占车 | 提议只是一条待协商消息；约定须在实际同意及可行性检查后成立 |
| 正常消息延迟导致提议来不及接受 | 新提议至少给出两步；收到的提议允许在出发前一步接受，两种时限明确分开；不会静默修改模型填写的时间 |
| 收件人名单被算作同意 | 逐人记录送达、处理、回应，仅使用实际同意者 |
| 按旧约定覆盖当前改期意图 | 执行须同时匹配当前步、当前意图、明确约定编号、成员、车辆和路线 |
| 私有计划一直为 None | 接入 1–3 步持续计划；没有修订就保留，有修订留历史，失败写回，执行完成更新状态 |
| 改期后旧约定继续占用资源 | 允许明确取消及重新提议；取消通知回到参与居民，版本关系保留 |
| 接受失败原因只在后台 | 协议反馈明确送达相关居民，记录来源消息及时间 |
| 接受阶段部分取消、后续又失败 | 先验证全部冲突，再整体完成替换，避免失败的修订破坏旧约定 |
| 仲裁前已改变共享状态 | resolve 阶段只验证；车辆、约定和位置变化在 apply 阶段提交 |
| 请求解释文字超长导致失败 | 对说明文字使用有界截取，行动与资源等行为字段保持严格校验 |

模型仍可选择留守、独自离开、拒绝提议或求助。修复不强迫家庭共同撤离，不把高撤离率作为通过标准。

## 本次真实小样本

- 原画像第 1、2、5、7 户：共 12 名成员、7 名决策居民，覆盖独居、双人、有照护成员和无车家庭。
- Full，seed=7201，12 步，每步 30 分钟。保持原建议令第 3 步、强制令第 7 步、封路第 9 步。
- DeepSeek-V4-Flash，通过原 Packy 接口；temperature=0，thinking enabled，max_tokens=32768。
- 并发 4，请求超时 600 秒，最多 120 次供应商请求，总墙钟上限 30 分钟；内部估价熔断为 2 美元，不等于已核实账单价格。
- 本轮修正提议时间说明后使用新缓存；遇到 HTTP 520 后，只复用相同输入的成功响应，从初态重走，不拼接事件日志。暂时性服务错误最多尝试 3 次，间隔 60/120 秒；鉴权及余额等不可重试错误仍立即中止。

## 统计口径

1. 官方信息首次送达人数：固定以 7 名决策居民为观察对象，保留每次送达时刻与来源。
2. 首次实际出发人数：执行成功、意图时间、约定时间与位置变化必须一致。
3. 多人约定：至少两位决策成员明确同意且可行性检查通过；自动单人出发单列。
4. 多人约定实际执行：按约定编号连接执行结果，不能把“已同意”当作“已出发”。
5. 家庭终态：使用全部 12 名成员的名册计算全员安全、部分安全与窗口内尚未出发。
6. 计划持续性、消息送达与失败后更新：从决策前后快照、实际模型输入、协议反馈与计划历史核对。

软件合法性检查不是社会真实性得分。四户结果是修复核验和图表预览，不替代 24/100 户正式结果。seek_help/offer_help 表示请求或提供帮助的意图；没有实际转移记录时，不计作接送或救助完成。
