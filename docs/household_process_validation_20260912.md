# 家庭协商实验：实现范围、固定场景与评价

本轮把论文已经声明的家庭内部协商机制做实。论文 `main.tex` 的家庭协议要求参与决策者和车辆属于同一家庭；本轮保留这个范围。邻居仍可交换信息和表达求助，但当前没有跨家庭接送、步行撤离或返程接人的执行能力。该限制必须出现在实际模型输入中，不能等失败后只返回含糊的“人员不合法”。

## 实现与核验

- 决策输入新增 `coordination_capabilities`，明确可独立同意的成员、被照护随行成员、车辆、消息地址及交通能力范围。
- 协议反馈区分跨家庭接送不支持、被照护成员填写位置错误、没有可达收件人等原因，保留违规成员和解释；不替模型改写成员名单或强制其同意。
- 显式需要执行协助的成年人也检查照护安排；给自己指定照护者不能满足需要他人协助的约束。
- 原有已创建共识状态检查保留。另增形成机会核验，直接从原始提案、实际收到的信息、成员回应及资源状态重建“应当形成／不得形成”，不把协议自身返回的 accepted 当作标准答案。
- 形成机会的正向和负向分母分别报告。若自然运行只有无效或未同意的提案，正向项仍为 N/A，不能用负向零错误冒充协商能力已经得到验证。

## 固定场景运行

案例与预期在 `disastersociety/experiments/carr/process_suite/cases_v1.json`，运行器为 `scripts/run_household_process_suite.py`。它直接调用实际居民、交互、家庭和世界模块，固定输入行为，既检验有效过程也检验异常过程，不调用模型服务。

```sh
cd disastersociety
python -m scripts.run_household_process_suite --output experiments/carr/runs/process_validation_new
python -m scripts.check_e1_process --output experiments/carr/runs/complete_process_new
python -m scripts.evaluate_e1_run \
  --run experiments/carr/runs/complete_process_new/offline_process \
  --output experiments/carr/runs/complete_process_new_evaluation
```

在已安装的项目环境运行；也可按根 README 使用 uv。每条命令使用新目录，保留旧结果。场景结果包括每项预期、通过或失败原因、完整过程、代码哈希和冻结案例哈希；一个案例的全部必要断言通过才计为通过。多条断言不当作多个独立案例。

案例覆盖：有效接受、部分接受、拒绝、未送达、普通通知、版本对应、重复接受、过期、撤回后执行、封路、新路线重议、缺少当前出发意图、容量、人员角色、协助与照护、空收件人、实际能力输入和允许独立出发。

这批案例包含先前开发试运行发现的问题，属于固定的开发过程验证集，不能称为从未接触的独立测试集。修复前后结果是工程修复验证，不是论文算法基线对照。

## 五项指标如何放进实验

保留原有五项，但分成两个实验表，避免把含义不同的数字相加。

| 实验 | 指标 | 可以支持什么 |
|---|---|---|
| 自主仿真方法比较 | 行为合理性；观察／接收错误；家庭共识状态错误；意图／执行混淆错误 | 同样输入和能力下，行为过程是否连贯，以及记录是否可靠 |
| 固定场景过程检查 | 场景检查通过数／全部案例数，并列各组覆盖 | 在列出的有效与异常输入下，消息、共识和执行转换是否正确 |

前者的行为由真实模型生成；后者的行为输入按案例固定。因此后者不能计入真实模型行为分数，也不能把其共识机会数挪入自然运行的分母。

状态错误率可能在所有共用程序的基线中都为零，届时它们作为共同的正确性证据；不能写成完整方法更优。自然运行没有共识时仍如实报告，同时用固定场景确认这条程序路径不是根本无法走通。

行为评审保留固定量表、完整轨迹、实际决策输入与逐条理由。简单的一次决策住户和经历长期协商的住户应另报行为覆盖，不能只看整体均分。不给撤离成功自动加分，不因拒绝或等待自动扣分。正式比较前固定量表及案例选择，再匿名评分。

## 下一轮主实验的具体准备

先在同一模型、同一合成家庭输入、同一信息投递和世界规则下，接入完整方法与基础生成式代理两个条件。基础代理必须使用同样的合法动作和家庭协议接口，不以故意删掉物理约束制造记录错误；它的私有记忆、计划和承诺跟踪实现差异要逐项写清。不能把自制基线直接命名为某篇论文的完整复现。该基线尚未在本轮实现或运行。

在开始付费对照之前固定：家庭样本、事件与种子、每步时间、模型与请求预算、终止条件、完整日志字段、评分量表。场景应包含有至少两名决策成员、可用共享车辆及明确照护关系的家庭，让协商成为可发生的选择；居民仍可拒绝、分开或独立行动，不以自然运行必须形成多少共识作为验收标准。全部方法使用同一批家庭，不能看到分数后挑选住户。

先做两个条件的一组配对小试，验证接口一致、真实调用与完整评价，再确定正式重复次数。不同种子运行才是评估场景随机性的重复；同一社会网络中的每次决策不能假定为独立样本。消融沿用同一评价，只逐项移除已明确界定的功能；执行反馈和路况更新不能混着移除却只解释其中一个。

本轮没有启动新的付费仿真、方法对照或消融，没有改写原始运行、旧评分或论文数值。新的过程检查结果单独保存；旧 8 户的行为评分不是本轮修复后的模型效果。
