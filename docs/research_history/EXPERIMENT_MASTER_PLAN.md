## 1. 总体判断

### 1.1 项目现在处在什么水平

方法方向已经确定，系统不是从零开始：通用事件循环、居民状态、家庭资源、消息生命周期、道路与车辆仲裁、记忆/反馈/规划/互动开关、真实模型网关、日志与 provenance 都已经实现到研究原型水平。调查清洗、PUMS 整户 donor、家庭级边际拟合和受控 Carr-S 机制 runner 也已接通。

但是，论文的“正式结果层”尚未完成。当前最接近正式主结果的是 E2 v8 的 60 格机制矩阵；E1 经验实验尚未运行，而且刚发现原 v1 居民画像不足，必须在付费执行前修订。E3 正式稳健性、规模实验和 H1 盲法评价也尚未完成。因此当前可以写完整 Methods 和 Evaluation Design，不能写完成式 Results、摘要发现或“行为真实性已经通过”。

### 1.2 为什么以前看起来做了很多实验

此前的运行实际上包含三种不同性质：

1. **工程验证**：mock、单元测试、连通性检查、确定性重放，回答代码路径是否接通；
2. **开发 pilot**：小户数、小 seed 的真实模型运行，目的是发现消息、计划、反馈和后端问题；
3. **出版用途实验**：冻结样本、条件、指标和排除规则后完整执行，并报告区间、MCSE、方向稳定性和失败情况。

前两类是必要研发过程，但不能按“正式实验数量”累计。论文主结果只认第三类以及经过核验的外部数据参照。

## 3. S0：系统验证与因果不变量

### 3.1 目的

证明平台实现的过程是真的执行了，而不是 prompt 里声称“已经记住、已经沟通、已经撤离”。

### 3.2 已完成

- 通用事件驱动 kernel 已实现；
- 每步先收集意图，再由 World 批量仲裁，最后提交执行结果；
- 被拒绝的撤离不会提前写入居民物理状态；
- 家庭消息经过 `sent → delivered → processed → accepted/rejected`；
- 车辆、依赖成员、路线容量和共同承诺由系统对象检查，不由 LLM 自行宣布；
- 运行有 `VALID / INVALID / ABORTED` 终态；
- 网关记录成功、失败、fallback、tokens、内部成本估算和调用日志；
- 命名随机流支持 full/drop-one 的共同外生随机性；
- 2026-08-02 在项目 `.venv` 完整重跑为 `91 passed in 8.06s`，包含本轮 Q13.6 精确映射回归测试；投稿前仍须按冻结依赖再复跑一次。

### 3.3 mock 的正确位置

mock 只保留在 S0：单元测试、接口测试、确定性重放和不变量检查。历史 mock 机制矩阵不得再称为行为实验、效果 pilot 或论文证据。

### 3.4 还缺什么

- 正式实验完成后审计全部 run 的终态、失败原因和 provenance；
- 对最终 100/500/1000 规模运行报告内存、吞吐和稳定规模；
- 提交前冻结环境依赖、运行命令和测试结果。

## 4. D0：数据、人口与场景资产

### 4.1 Carr 调查数据

已核验：原始 Qualtrics 有 647 条原始响应，335 条完成答卷，330 条 `Q9.1` 有效结果，其中 293 人撤离、37 人未撤离；292 名撤离者有完整撤离日期和时间。`Q9.1` 是是否撤离，`Q13.3/Q13.4` 是撤离日期与时间，历史标签覆盖错误已经修复。

2026-08-02 的完整字段审计又发现并修复一个不影响上述主参照、但必须登记的派生列错误：问卷/CSV 表头明确 `Q13.6_1` 是出发时可见火势、`Q13.6_2` 是烟雾、`Q13.6_3` 是官方压力；旧清洗脚本曾把 fire/smoke 错映射为 `_2/_3`。这两列一直是 post-outcome 且已从预测和 E1 主参照排除，因此 Q9.1、撤离时间、渠道和既有 Carr-R 输入不受影响；修复后增加了精确映射测试。

调查是自愿 respondent sample，不是加权总体真值。样本中零车辆家庭为 0，因此不能用它验证无车家庭差异；只允许报告该指标不可估计，不能换一个有利指标代替。

### 4.2 PUMS/ACS 人口

已完成的基础：

- 4,317 个符合过滤条件的 donor household；
- 9,968 条通过 `SERIALNO` 连接的 person records；
- `NP` 与成员数一致，同户 `SPORDER` 唯一，每户参考人合法；
- `WGTP` 作为基础权重；
- 48 tract 的收入、车辆、家庭结构和老年成员四组家庭级边际拟合；
- 抽中 donor household 时整户带入成员，重新生成 synthetic household/resident ID；
- 原始 `SERIALNO` 只留在受限 provenance；
- 1000 户 pilot 已生成并通过家庭级 fractional fit，但 person age 未拟合且存在明显 tract 偏差。

因此，当前可以说“家庭级边际拟合 + 整户 donor 重采样已实现”，不能说“成员级联合分布或 tract 成员画像已校准”。

### 4.3 场景资产

- 2018 TIGER/Line 道路派生的西 Redding 双路线可用于受控实验；
- final perimeter 只能作为空间锚点，不是危险时序；
- 当前道路阻断是算法控制的扰动，不是 Carr 历史关闭；
- 官方预警接收边际用于 delivery calibration，不能再作为独立外部验证；
- 调查 `Q6.1/Q7.1` 是多选渠道 prevalence，不是 first-heard distribution。

原始 PUMS ZIP 仍包含当前 donor v1 未保留的字段。E1 v2 应在新目录生成 donor/person v2，不覆盖 v1，至少考虑：

## 5. R0：Carr-R 真实受访者辅助诊断

### 5.1 原实验到底做了什么

R0 不是多步智能体仿真。它对每名真实问卷受访者做一次判断，输入只有：

1. 年龄段；
2. 家庭人数；
3. 家庭车辆数；
4. 家庭收入段。

传统模型在 198 人 train 上拟合，DeepSeek 对 66 人 validation 各调用一次；validation 有 59 名撤离者、7 名未撤离者。

### 5.2 已完成结果

- prevalence 常数：Macro-F1 0.472，7 名未撤离者识别 0 人；
-普通 LR：Macro-F1 0.459，未撤离者识别 0 人；
- balanced LR/RF：各只识别 1/7，但把大量撤离者错判为未撤离；
- DeepSeek 四字段 live：Macro-F1 0.463、Brier 0.127、ECE 0.178，混淆矩阵 `[[0,7],[2,57]]`；
- 加一个所有人相同的 Carr 事前情境后，Macro-F1 和混淆矩阵不变，Brier 变为 0.145、ECE 变为 0.197，仍识别 0/7 未撤离者。

这些结果说明的是“这四个粗字段不足”，不是“平台社会过程无效”，也不是“DeepSeek 一定不能判断撤离”。

### 5.3 2026-08-02 的完整数据信号诊断

为回答四字段是否遗漏关键信息，已对去标识后的完整 330 人数据做开发性诊断。问卷确实还有结构属性、命令暴露和回忆性决策前信念。四字段在重复分层诊断中的排序能力接近随机；加入全部候选字段后可提高排序和少数类召回，但主要增益来自命令暴露和回忆性信念，而这些字段存在时序、回忆偏差或同源校准问题。该诊断不是正式模型结果。

37 名未撤离者报告的主要原因包括：未收到命令 14 人次、认为火势不会威胁自己 12、人不想离开 11、保护财产免受火灾 10、保护财产免遭盗窃 7、宠物去向不确定 3、交通顾虑 2。`Q10.1` 只对未撤离者提问，因此这些原因只能帮助解释缺失了什么状态，绝不能直接作为预测输入。

本次诊断按用户要求检查了完整数据中的特征—结果关系，因此原 66 人 test 不再是分析者未知的盲测集。当前状态必须改为 `OPENED_FOR_DIAGNOSTIC`；不得再把后续同数据结果称为 untouched test。历史 validation 运行发生时 test 确实尚未打开，这一历史事实可以保留。

### 5.4 R0 的处理决定

- 停止继续花钱做四字段 one-shot DeepSeek 分类；
- 不把 R0 作为论文成败门槛；
- 若保留，只在附录报告“信息受限诊断”和类别不平衡；
- 丰富字段的真正用途转入 E1 的居民状态初始化和动态事件输入；
- 如果未来仍要做个体预测，只能采用重新声明的交叉验证/外部数据，不再声称当前 test 是盲测；
- 任何新个体任务必须定义共同决策时点，否则“火灾期间曾收到命令”可能发生在某人已经撤离之后。

## 6. E1：经验合理性与社会过程

### 6.1 E1 真正要回答什么

E1 不要求逐人复刻问卷答案。它检验 Carr-S 生成的整体撤离比例、命令到出发时间、群体差异、家庭协调、资源约束和消息过程是否与经验材料及可执行约束相容。

### 6.2 已完成

问卷参照 v1.1 已生成：

- Q9.1 撤离率 0.8879，Wilson 95% CI 0.8493–0.9176；
- 一致且时间合法的首次命令到出发样本 n=186，中位 1 小时，5 小时内累计 0.7742；
- 肯定命令优先敏感性样本 n=194，5 小时内累计 0.7732；
- 年龄 65+、家庭 3+、收入低于 5 万美元的差异可估计，但区间均跨 0；
- 零车辆差异因调查中 n=0 不可估计。

这些是外部参照构建，不是模拟已经通过。

### 6.3 原 E1 v1 做了什么、为什么现在不能直接运行

v1 已实现 50 户、81 名决策成人、15 名依赖成员、实际家庭消息、受控社会图、真实 DeepSeek thinking、无预设出发时间的自然时序 runner，但尚未付费执行。

当前 prompt 的居民画像主要只有年龄、失能、家庭人数、收入、车辆和家庭结构。它缺少就业/工作义务、住房与财产、既往经验、宠物/牲畜、家庭决策角色、风险认知、命令信任、交通/住宿/成本顾虑。因此 v1 可以运行，却不足以承担行为经验合理性主张。

v1 还存在三个会削弱经验解释的控制假设：第一个成人自动成为 coordinator，而不是依据 `RELP` 或合成决策角色；车辆容量使用 `max(5, household size)`，基本预先消除了座位不足；所有家庭共享同一危险距离轨迹和 step-1 强制命令，和包含未收到/建议/强制命令混合暴露的 Carr 总体参照并不处于同一支持范围。v2 必须修订这些设计，或把 estimand 限定为相应的固定强制令情境。

v1 的冻结文件和代码应保留，状态改为 `SUPERSEDED_BEFORE_PAID_EXECUTION`。不删除、不覆盖，也不为了“前面已经写完”而继续花钱。

### 6.4 E1 v2 的居民输入结构

E1 v2 不把整份问卷复制进 prompt，而是把信息放进正确的状态层：

| 状态层 | 输入内容 | 来源/生成方式 | 何时对居民可见 |
|---|---|---|---|
| 居民静态属性 | 年龄、性别、教育、就业、工作时长/通勤、分项失能、家庭关系 | PUMS whole-household donor v2 | 仿真开始即存在 |
| 家庭共享约束 | 成员、儿童/老人/依赖、车辆、收入、住房类型/产权、空间资源 | PUMS housing/person donor v2 | 物理共享状态可见；私有认知不自动共享 |
| 合成潜在特质 | 既往撤离、宠物/牲畜、决策角色、社区联系、基础信任 | Carr 调查非结果字段的边际或完整 trait-block donor | 初始化时进入 persona/state；明确标记为 survey-informed synthetic trait |
| 初始信念/偏好 | 火势严重度与速度担忧、交通/住宿/燃油/成本顾虑、房屋/伤亡风险、财产保护、工作义务 | Carr `Q29.3/Q29.4` 的回忆性事前条目，禁止使用 Q9/Q10/Q13 结果字段 | 初始化为潜在状态；报告回忆偏差和同源数据边界 |
| 动态信息 | 强制/建议命令、渠道、时间、来源、清晰度、危险距离、道路状态、家庭/邻里消息 | EventPack、delivery model、World、Interaction | 只有实际送达并处理后才进入 inbox/memory |
| 执行反馈 | 路线关闭、车辆不可用、照护冲突、行动拒绝原因 | World 仲裁 | 行动被执行/拒绝后进入下一次决策 |
| 评价专用 | Q9.1、Q13.3/Q13.4、聚合时序、渠道 prevalence、外部群体差异 | Carr survey reference | 永不进入居民 prompt |
| 永久排除/泄漏 | Q10.1 不撤离原因、只对某结果分支提问的条目、Q13.6 出发时感知、结果后评价、自由文本 | Carr survey | 不作 runtime input；自由文本还受隐私限制 |

### 6.5 潜在特质如何合成才不作弊

推荐使用“完整 trait block donor + 禁止按 outcome 条件抽样”：

1. 只从原冻结 train 部分抽取预先允许的灾前/回忆性事前字段；完整数据诊断已经使 test 不再盲，但仍不得把 validation/test 用作画像 donor；
2. 删除 `Q9.1`、Q10、撤离时间、出发时感知及所有结果后字段；
3. 不按是否撤离建立两套画像，不训练 `P(trait | outcome)`；
4. 使用年龄段、家庭规模、车辆和收入等共同非结果字段做粗匹配后，从允许字段的完整 train trait block 整体重采样，以保留风险、成本、财产和信任之间的联合结构；
5. trait donor ID 只进受限 provenance，prompt 不出现真实 respondent ID；
6. PUMS 与 trait block 的匹配只使用事先允许的共同静态变量，或直接无条件加权抽样；
7. 把 18 个 Q29 条目预先压缩成有理论含义的风险担忧、撤离摩擦、生命/住房威胁、基础设施/救援、财产安全和工作义务量表；量表定义不能根据 Q9 结果调权；
8. 公开报告哪些维度来自 PUMS、哪些是调查边际、哪些完全是情境控制；
9. Q29 是火灾后回忆“决策前”状态，只能称 retrospective pre-decision belief，不能称独立实时测量。

同一 Carr 调查同时提供输入分布和 Q9/Q13 评价参照，会降低外部独立性。最强方案是增加独立调查/文献先验；若首篇论文只用 Carr，必须称 Carr-informed empirical reasonableness，而不是独立外部验证或总体真实性。

### 6.6 E1 v2 的运行设计

付费正式执行前依次通过：

1. **离线数据 QA**：每个居民所有字段有来源标签；无 Q9/Q10/Q13 泄漏；trait donor 不带身份；PUMS 家庭关系不被拆散；
2. **真实模型小型预检**：使用 DeepSeek thinking，不使用 mock，检查约 20 户、2 个新 seed 的画像是否被模型实际引用、行动是否有异质性、消息与约束是否闭环；
3. **协议冻结**：根据预检的 run-level 方差冻结户数、seed 数、最大时长、指标和停止规则；
4. **正式 full-only 运行**：E1 不做四模块 drop-one；它评估完整平台的自然时序社会过程。正式重复应同时改变 cohort seed 和 model/delivery seed，而不是永远固定同一 50 户只换模型随机性；
5. **统计**：每个 seed 先计算一个 run-level 结果，再报告跨 seed mean、SD、MCSE 和 t 区间；家庭/居民记录只作描述或使用聚类处理；
6. **盲评包**：从完成的真实轨迹中按预声明规则抽样，供 H1 使用。

### 6.7 E1 主要指标

- 焦点居民撤离比例与 Carr respondent reference 的差；
- 首次有效命令到实际出发的 CDF、分位数和区间；
- 年龄、家庭规模、收入等可对齐群体差异；
- 完整家庭安全出发、协调出发、依赖成员安全；
- 车辆冲突、依赖遗留、无效路线/资源请求；
- 家庭/邻里消息 `sent/delivered/processed/accepted/rejected` 漏斗；
- 求助与响应、信息覆盖与延迟；
- 轨迹盲法连贯性和约束合理性。

## 7. E2：四模块正式机制消融

### 7.1 E2 真正要回答什么

E2 不是预测 Carr 中谁撤离，也不是生成自然人口分布。它在同一个受控机会场景中移除一个模块，观察该模块目标过程和下游行为是否按预声明方向改变。

### 7.2 为什么 E2 不应在运行中加入全部问卷画像

E2 的作用是机制识别。所有条件必须共享相同家庭、初始私人主路线计划、道路关闭、消息机会和外生随机流。如果此时同时引入大量未经拟合的信念差异，会增加噪声并混淆“模块被移除”与“居民画像不同”。

因此：

- E2 保留受控且相同的画像/机会是合理设计；
- E1 才负责丰富异质画像和自然行为；
- E2 的简单画像不用于声称经验真实性；
- E2 r7 已冻结并运行，不能因 E1 新发现而中途换 persona。

### 7.3 条件与指标

五个条件：

1. full；
2. full − memory；
3. full − feedback；
4. full − planning；
5. full − interaction。

每个模块既有近端 manipulation check，也有非结构性下游指标：

| 模块 | 近端指标 | 下游指标 |
|---|---|---|
| Memory | 条件化预警保留/跨时记忆一致性 | 后续安全行动和重复错误 |
| Feedback | 主路线到备用路线的感知更新 | 关闭路线拒绝、适应延迟 |
| Planning | 成功重规划 | 完整家庭安全出发、约束违反 |
| Interaction | 关闭后可行共同承诺形成 | 协调出发、依赖成员与车辆冲突 |

### 7.4 已完成的开发结果

- 历史 mock 矩阵只证明代码接线；
- v3/v4/v5 真实模型运行暴露了后端、送达率、提议过期和指标定义问题；
- v6 修复消息时序与承诺可行性；
- v7 分离居民感知道路与真实 World，并统一机制作用机会；
- v8 把执行拒绝、车辆占用和承诺执行语义返回居民；
- v7 的 4 户 × 3 seed pilot 四项方向均为正，但样本太小；
- v8 三个 full 开发 run 改善了执行闭环，但不是正式对照。

### 7.5 当前正式运行

出版用途矩阵：8 户、5 条件、12 个全新 seed，共 60 个 `seed × condition` run，DeepSeek V4 Flash thinking-high。恢复协议 r7 与 r4–r6 的科学配置完全一致，只换协议/run身份并启用SDK级重试退避；2026-08-02按用户提速要求冻结6-lane并行amendment（每run并发6、总在途36、已完成格复用），墙钟目标从约10小时降到约3.5小时；不得与 r1–r6 拼接。

截至2026-08-02，r4 在10个`VALID`格后、r5 在第1–2步、r6 在19个`VALID`格后均因连接/源站错误停止并整体排除；r7 已按用户明确授权冻结为完整60格重跑，两条 lane 正在执行。这里不读取或报告中间机制方向；所有单格和未完成矩阵仍是`PILOT`，必须等60格完整审计。

### 7.6 E2 完成标准

- 60 格全部有可审计终态，或按冻结规则停止并透明排除；
- 不跨 attempt 拼接；
- 每个 seed 形成 full-drop 配对差；
- 报告均值、SD、MCSE、95% t 区间、正方向 seed 比例；
- 同时报近端和下游指标；
- 报告失败、fallback、墙钟、tokens、内部成本估算；
- 不把受控路线阻断称为历史 Carr 重建。

## 8. E3：稳健性与效率

### 8.1 已完成

v6 小型跨模型 pilot 在 DeepSeek、Qwen3.5-Plus、GLM-5、MiniMax-M2.7 上完成 40 个最终有效格。memory 方向最稳定；feedback 明显模型敏感；planning/interaction 仍有模型和机会敏感性。因为它使用旧 v6、2 户和 2 seed，只能作 pilot。

### 8.2 仍需正式执行的三部分

#### E3a：等价提示敏感性

- 在最终 v8/E1-v2 语义上写至少两个等价 prompt；
- 不改变可用信息、schema、机制开关或行动集合；
- 用相同 cohort/seed 比较方向、rank、约束率和失败率；
- 不按结果挑选“最好 prompt”。

#### E3b：有限跨模型复核

- 不需要所有实验都跑四个模型；
- 只对论文最关键的 E2 模块方向和 E1 aggregate full-only 做有限复核；
- 预先选择 1–2 个替代模型族与少量独立 seed；
- 报告同一 Packy 代理边界，不能声称跨提供商独立性。

#### E3c：100/500/1000 智能体规模与效率

- 使用真实模型后端，不能把 mock 规模结果当论文证据；
- 依赖成员和未被事件唤醒者不必每步调用 LLM；

- 每个规模至少多个独立 seed；
- 指标包括完成率、墙钟、吞吐、峰值内存、tokens、内部成本、失败/fallback、事件和消息积压；
- “1000 agents”只支持运行包络，不支持现实真实性。

## 9. H1：盲法人工/专家评价

### 9.1 数据来源

只能使用 E1 v2 的真实模型轨迹。不能用手写轨迹、mock 轨迹或 LLM 自评冒充人类。

### 9.2 建议设计

- 预声明抽样：覆盖撤离/未撤离、单/多成人、有/无依赖、不同约束复杂度；
- 去掉模型名、seed、内部条件名和任何身份；
- 至少两名独立评分者；
- 评分维度：信息使用是否有依据、跨时一致性、计划可执行性、家庭协调、对失败反馈的适应、整体可信度；
- 记录评分者背景、培训材料和盲法；
- 报告一致性（如加权 kappa/ICC，视量表而定）和分歧案例；
- 专家不足时可做普通人工评价，但必须准确命名，不能写成专家验证。

## 11. 从现在到论文 Results 的唯一执行顺序

### 阶段 A：当前立即进行

1. 让 E2 r7 在冻结协议下跑完；不修改其 cohort、prompt、条件、seed 或指标；
2. 离线实现 E1 v2 丰富画像，不启动与 E2 重叠的付费任务；
3. 生成 donor v2 与 trait-block QA，保留所有来源与泄漏检查；
4. 把 R0 改为辅助诊断，并记录 test 已用于完整数据诊断。

### 阶段 B：E2 结束后

1. 对完整 E2 矩阵做 hash、终态、配对、区间、MCSE、方向和成本审计；
2. 若 E2 因非 VALID 停止，按协议报告，不读取有利方向后临时挑格；
3. 运行 E1 v2 小型真实 DeepSeek 预检；
4. 根据预检方差和画像行为冻结 E1 v2 正式户数/seed，不沿用已失效的 v1 冻结。

### 阶段 C：经验与人工评价

1. 完成 E1 v2 全部正式 full-only runs；
2. 汇总撤离率、时序、群体差异、家庭约束和消息漏斗；
3. 生成盲评包并由真实独立评分者完成 H1；
4. 若无法获得专家，只降低命名和主张，不伪造评分。

### 阶段 D：稳健性与效率

1. 做等价提示敏感性；
2. 做有限跨模型复核；
3. 做 100/500/1000 真实后端规模实验；
4. 汇总稳定性、tokens、成本、吞吐、失败和最大稳定规模。

### 阶段 E：论文收尾

1. 只把 `VERIFIED` 的限定结果写入 Results；
2. `PILOT` 只进入方法开发、附录或限制；
3. `INVALID_FOR_CLAIM` 只说明为何不能使用；
4. 更新摘要的两至三项正式发现；
5. 写 Discussion 的经验边界、同源数据、受控场景、person-level 未校准、模型/代理和成本限制。

## 13. 最终的“论文完成”判定

论文不需要每项实验都得到漂亮结果，但必须得到完整、可解释、没有泄漏的结果。最低完成条件是：

1. S0/D0 的最终审计通过；
2. E2 完整矩阵有可报告的配对估计和边界；
3. E1 v2 有真实模型的群体/家庭结果，并与合法参照比较；
4. 至少一种真实人工评价完成；
5. E3 至少覆盖 seed、等价提示、有限跨模型和三个规模点；
6. 所有失败、无效格、同源校准和不可估计指标如实报告；
7. 论文根据结果缩小主张，而不是根据主张重写结果。

在这些条件完成前，准确表述是：

> DisasterSociety 的方法与研究原型已经建立，系统和数据基础较强，正式机制矩阵正在执行；经验行为评价、丰富居民画像、稳健性、规模和盲法评价仍在完成过程中。
