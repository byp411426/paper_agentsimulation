# 实验评价基础修复（2026-09-09）

本次修复当前源码、生成独立的新输入版本，并完成离线验证。旧的三次 24 户运行、未完成的 100 户运行、冻结实现及论文结果均保留原样。

这不是“所有代码都错了”的结论。旧记录中三项状态检查仍为 0/124、0/12、0/28；它们有明确覆盖范围，不能证明行为合理性或方法优越性。

## 已修改的内容

| 问题 | 修改及影响 |
| --- | --- |
| HHT=5、6 的独居标签写反 | 按 2018 ACS PUMS HHT 定义修正映射。HHT=4、6 独居；5、7 非独居。只影响新生成的输入。 |
| 矛盾人物背景仍可进入模型 | 在画像组装和运行入口校验人数、独居标签、重复身份、成员角色、协调人及车辆数量。错误输入在模型调用前报错。 |
| 实际输入文件沿用旧标签 | 使用原始合成住户 CSV 的 HHT、NP，另生成 24 户新输入。仅 4 户的 household_structure 改变，逐字段确认其他内容不变；不是修改旧行为的解释材料。 |
| 向同住成员 ID 发信却走社区传播 | 此类定向消息使用 household_dm；不扩大到全家庭广播。跨家庭消息继续受社交关系和社区传播条件约束。此修复可能影响新行为。 |
| 私人记录共享可变对象 | 接收内容、初始道路认知使用独立副本；接收内容不带其他人的全局投递、接受状态。避免后续账本变化反过来改写旧接收内容。 |
| 重复投递重置接收／处理状态 | 同一 receipt_id、message_id 幂等处理；正式警报验证收件人身份。 |
| 决策结束后才来的通知仍可能被记成这次已经处理 | 处理范围限定为该次决策实际看到的收件箱。处理阶段才送来的通知留到下次决策。 |
| 同一个共识 ID 可被换成不同方案 | 拒绝复用 ID 改变条款；不允许无旧方案参与者授权的替代操作。原本相同且有效的重复接受可以幂等返回。 |
| 拒绝结果仍写 executed_action=evacuate | 新结果分别保存 requested_action 与 executed_action；拒绝时 executed_action=null，记忆及反馈采用相同语义。旧记录仍须结合 status 解读。 |
| 缺少资源与局部观察证据 | 新日志增加车辆位置、占用／预留状态、道路使用量、共同方案照护映射、执行前后资源变化；实际决策观察有编号、居民、时间、阶段及内容。局部观察来源目前覆盖危险距离和共享资源可见状态。 |
| 名为时间线的文件只有末态 | resident_state_timeline.jsonl 改为逐步、逐居民记录；末态另写 resident_terminal_states.jsonl。新格式附 log_schema.json。 |
| 无地理数据时受 Python 随机哈希影响 | 合成位置由实验种子和家庭 ID 确定，同住成员共用位置；不再依赖 Python hash()。新位置策略会影响关系网络，须与旧运行区分。 |
| 中途失败后仍可能有并发任务继续写日志 | 取消并等待同一步剩余任务退出，再结束运行；最后完成步数不再误写为正在失败的步数。在线后端关闭留在创建它的事件循环内。 |
| 直接调用运行函数可能覆盖原日志 | 核心运行入口也检查已有仿真文件；增加 --validate-only 输入检查入口。 |

HHT 的依据是前次核验已查阅的美国人口普查局 [2018 ACS PUMS 数据字典](https://www2.census.gov/programs-surveys/acs/tech_docs/pums/data_dict/PUMS_Data_Dictionary_2018.pdf)，印刷第 13 页。本轮没有重新搜索文献。

## 可重复运行的检查

以下命令在仓库的 `disastersociety/` 目录运行。依赖项目环境及开发测试依赖；无需配置密钥。

```bash
# 检查新 24 户输入；不创建模型调用
python -m scripts.run_carr_e1_v2_preflight \
  --config experiments/carr/configs/carr_s_e1_empirical_v2_preflight.yaml \
  --profiles experiments/carr/inputs/evaluation_repair_20260909/profiles.jsonl \
  --n-households 24 --validate-only

# 两户、三名决策居民、八步的固定脚本流程；输出目录必须是新的
python -m scripts.check_e1_process --output /tmp/e1_process_check_new

# 复核原来选中的 24 户、seed7201、attempt3 完整运行
python -m scripts.audit_archived_run --repo .. --output /tmp/e1_archived_audit_new

# 离线回归测试
python -m pytest tests -q -ra
```

旧日志评价脚本固定核验 9 月 5 日批次的已接受运行，保留原版本的消息渠道、字段语义和输入分配；不会拿修复后的规则反过来判旧运行。它导出全过程及三项核验结果，缺少覆盖的部分明写限制。这个入口不是任意版本日志都能读的通用评价器。

两户流程包含共同提议、有效接受、封路拒绝、改约、重新接受、实际出发及另一户单人出发。固定脚本仅用于验证程序，不能拿去评行为合理性，也不能把其 10 项断言写成论文正式场景通过率。

测试还覆盖错误接收、旧同意套新方案、拒绝却改变位置、未决策成员被移动等注入错误，检查评价器能够发现问题。完整的测试计数与执行证据见同目录 `evaluation_repair_20260909_verification.json`。

## 对主实验的影响

保持已讨论的评价分工：主对比使用行为合理性及三项状态错误率；固定场景过程检查单列。撤离更多、更快或拒绝更少，不自动代表社会模拟更好。

本次增加的是代码正确性和可核验证据，不是正式主实验结果。行为合理性评分、规则／通用代理的公平对比，以及新日志的正式全范围评价尚未完成；消融开关的独立性也未在本次全面审定。

新的行为可能受修正画像、消息投递、处理时序、认知副本及关系网络影响。新的提示输入和缓存键也可能变化。因此新运行必须使用新的输出位置和清楚的版本记录，不能与旧种子结果直接拼接后计算一个均值。

现有世界仍采用瞬时转移到安全区的抽象；车辆没有持续在途占用，到安全区后居民不继续决策。求助／提供帮助本身不等于接送完成。本次没有增加返程接送，也没有把等待、分歧和失败改成“正确撤离”。
